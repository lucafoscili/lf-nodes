# LF Nodes 4.0.0

Released with maintainer acceptance of the optional H3 HD motion/audio quality.
See [release readiness](https://github.com/lucafoscili/lf-nodes/blob/v4.0.0/docs/RELEASE_READINESS.md)
for measured gates and verification limits; this release does not declare a
full E2E pass.

## Breaking Runner migration: TRELLIS.2

The v3.0.0 Runner catalogue shipped two wrapper-based TRELLIS.2 cards. In 4.0.0,
`trellis2_multiview_to_textured_mesh` is removed, and
`trellis2_image_to_textured_mesh` keeps its ID but uses ComfyUI Core's native
TRELLIS.2 graph and a different model package. The major version reflects this
Runner compatibility break, not a reordering of existing public LF node sockets.

If you use either card:

1. Update ComfyUI to a version with the native TRELLIS.2 nodes and restart
   ComfyUI after updating LF Nodes so Runner loads the current definitions.
2. For `trellis2_image_to_textured_mesh`, install the native loader files:
   `trellis_2_int8_convrot.safetensors`, `trellis_2_shape_vae_bf16.safetensors`,
   `trellis_2_texture_vae_bf16.safetensors`, `dino_v3_vit_l.safetensors`, and
   `birefnet.safetensors`. The previous wrapper's
   `microsoft/TRELLIS.2-4B` package and DINOv3 directory package do not satisfy
   these loader choices. Select the current card or download its new graph;
   check Runner's **Setup required** details for missing files or nodes before
   running. See [native TRELLIS.2 requirements](https://github.com/lucafoscili/lf-nodes/blob/v4.0.0/docs/WORKFLOW_RUNNER.md#trellis2-workflows).
3. Remove or revise callers and custom orchestras that reference
   `trellis2_multiview_to_textured_mesh`. There is no shipped multi-view
   replacement. Use the native single-image card only if one source image is
   sufficient for your task; it does not consume the former front/back/side
   inputs or provide equivalent multi-view reconstruction.
4. Review previously downloaded and custom graphs separately: updating LF
   Nodes does not rewrite them or replace their wrapper nodes. Preserve an
   existing working environment if you still need those graphs while choosing
   a migration. This release does not restore the retired extension or
   guarantee old wrapper graphs will run on an updated Core installation.

LF Nodes does not download either model package automatically. The native card
still produces a textured GLB and a saved front preview; hidden surfaces are
inferred. It adds no guarantee of watertightness, manifold topology, production
UVs, rigging, or game readiness.

## Highlights since v3.0.0

- **Simple idea to H3 video:** atomic prose-only Prompt Maker, optional review,
  vision and up to nine ordered references with independent dimensions. The
  phone-friendly Idea to Video orchestra hands the exact prose to the renderer.
- **Optional learned HD output:** native H3 generation followed by
  four-step latent refinement. Available across H3 rendering blocks and their
  three orchestras; Standard remains the default. Requires the optional external
  upscaler extension and checkpoint. See [HD setup](https://github.com/lucafoscili/lf-nodes/blob/v4.0.0/docs/llm/h3-hd-output.md).
- **Local model ergonomics:** local chat completions and exact-instance LM Studio
  load/unload nodes, including authenticated native discovery and model lifecycle.
  The writer can release its model before the video stage to free memory.
- **Reversible image editing:** named image-region extraction/composition and
  source-safe RGBA layer loading/composition. One editor session can combine
  base-image regions, fabric layers and optional cut masks; original alpha is
  locked by default. Labels and selection identity survive reordering and
  reload. See [image regions](https://github.com/lucafoscili/lf-nodes/blob/v4.0.0/docs/IMAGE_REGIONS.md) and
  [image layers](https://github.com/lucafoscili/lf-nodes/blob/v4.0.0/docs/IMAGE_LAYERS.md).
- **Animated GLB tools:** replace a selected material's texture without flattening
  its mesh, UVs, materials or animation, and scale selected joint subtrees around
  explicit anchors. Source files remain unchanged; stock Comfy 3D previews and
  savers consume the results. See [texture replacement](https://github.com/lucafoscili/lf-nodes/blob/v4.0.0/docs/GLB_TEXTURE.md) and
  [joint scaling](https://github.com/lucafoscili/lf-nodes/blob/v4.0.0/docs/GLB_SCALE.md). Character-specific Studio recipes remain
  consumer-owned, not new shipped Runner catalogue entries.
- **Sprite, tile and media tools:** settled-frame selection, loop-segment
  selection, seamless textures, isometric diamond tiles, audio saving/preview,
  and JSON key lookup by index.
- **Native RMBG-2.0:** the existing Background Remover gains a local RMBG-2.0
  choice, invocation-scoped model loading and source-alpha preservation.
  Shipped sprite/turnaround cards no longer depend on VNCCS. The default
  `u2net` choice, ordered mixed-size lists and all seven sockets are preserved.
- **Runner assemblies and history:** reusable multi-block orchestras, named
  artifact/text handoffs and durable child-run outputs, alongside proxy/auth
  hardening and phone-oriented controls.
- **Clearer catalogue:** separate LF Nodes and custom collections, quick section
  links, concise card descriptions, and seven new previews from real workflow runs,
  including a full stereo waveform of the user-accepted hearth sound effect.
  Unrelated queue/run updates now preserve mounted cards instead of restarting
  the custom collections' fade-in animations.
- **Compatibility fixes:** RGB editor effects and inpainting retain source alpha
  on RGBA images; file selection follows the selected file rather than a stale
  position; proxy URLs with hashes/query strings resolve frontend assets correctly.
  TRELLIS remesh/decimation inputs use native DynamicCombo wire formatting.
- **Release coverage:** the suite now exposes 154 public LF node types. The
  publication gate checks their canonical Titanic inventory separately from
  hydration and execution. Live gate outcomes and intentionally unexecuted cases
  are recorded in readiness notes, not inferred from unit-test totals.

## Compatibility and setup

Sixteen public nodes have been added since v3.0.0. This batch changes no existing
public output socket order. Existing H3 workflows keep Standard output unless HD
is explicitly selected. HD does not combine with Turbo; select Kitchen 20.

RMBG-2.0 now runs through LF's public Background Remover. Shipped sprite and
turnaround cards need its trusted four-file local model package, not VNCCS.
See [setup, licensing and output contracts](https://github.com/lucafoscili/lf-nodes/blob/v4.0.0/docs/BACKGROUND_REMOVER.md).
Older/downloaded/custom graphs containing `VNCCS_RMBG2` are not rewritten;
the [explicit temporary repair](https://github.com/lucafoscili/lf-nodes/blob/v4.0.0/docs/compatibility/vnccs-rmbg.md) remains available
for affected external versions. Nothing patches or uninstalls VNCCS automatically.

For users of the unreleased compiler-era Prompt Maker: `validation_report` now
reports authoring/review status, **not schema validation** (`valid: null`,
`validation: not_performed`). `visual_inventory` keeps its socket for compatibility
but does not claim extracted facts. See [Prompt Maker](https://github.com/lucafoscili/lf-nodes/blob/v4.0.0/docs/llm/h3-prompt-maker.md)
before relying on those older receipts. Review is not a correctness guarantee.

Restart Comfy to load updated Python nodes/workflow definitions. Existing
compatible local models are reused; TRELLIS.2's native migration requires the
different files listed above. No new model is downloaded automatically. LMS
lifecycle operations require workflow ownership of the selected instance;
failed/cancelled authoring may leave it loaded. See [LMS lifecycle](https://github.com/lucafoscili/lf-nodes/blob/v4.0.0/docs/llm/lms-models.md).

Region/layer compositors require exact ordered editor outputs and the original
source data; they do not guess pairing or overwrite source assets. Cut masks can
reduce or restore original coverage, not paint outside it. GLB transforms accept
self-contained GLB 2 inputs; texture replacement handles one image/material per
invocation, and joint scaling requires an explicit target recipe. These limits
are intentional and documented in the feature guides above.

If upgrading from before v3.0.0, also follow that version's
[`LF_ExtractPromptFromLoraTag` socket migration](https://github.com/lucafoscili/lf-nodes/blob/v4.0.0/docs/releases/3.0.0.md#breaking-migration-lf_extractpromptfromloratag).
That migration was already part of v3.0.0.

## Verification boundaries

Recorded checks include CPU publication contracts, frontend tests and a
production build, a clean source/frontend package rehearsal, and live Titanic
hydration plus selected branch executions. The canonical specimen contains
390 nodes and 515 links and covers all 154 public LF node types; inventory and
hydration do not establish that every branch executed.

Live evidence includes selected H3/HD, media, local model lifecycle,
region/layer, GLB and sprite paths. Direct RMBG-2.0 was inspected on a bounded
same-frame comparison and mixed-size execution; matte quality is not certified
for every subject. The package rehearsal reused the installed Python environment
and did not establish a blank-machine GPU installation. Luca accepted the
scoped optional HD motion/audio quality on 2026-10-02. Remaining provider,
model-heavy and interactive-editor cases and catalogue samples retain the
limits recorded in
[release readiness](https://github.com/lucafoscili/lf-nodes/blob/v4.0.0/docs/RELEASE_READINESS.md).
This sign-off does not establish exhaustive E2E or universal media quality.
